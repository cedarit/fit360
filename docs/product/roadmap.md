# Fit360 roadmap

Fit360 grows in phases that follow its own story: **learn → teach → practise → share → business**. Each phase has an exit check. The next phase starts only when the check is met or Pankaj decides to move on.

## Phase 0 — Foundations (now)

- Rewrite the project docs for the business direction (done 2026-09-25).
- Set up the Git repository, the Jira project (`FIT`) and the tooling for Claude and Codex.
- Approve the Term 1 structure and the module objectives.

**Exit check:** Term 1 structure approved; repository and Jira live.

## Phase 1 — Learn and teach

- Write the Term 1 lessons in `docs/curriculum/`, with sources.
- Publish each lesson as a YouTube video. Track which topics get watched, commented on and asked about.
- Produce the first vertical slice: one complete lesson plus the Lat Pulldown Lab.

**Exit check:** first vertical slice approved; a steady run of Fit360 videos published; a list of the questions viewers actually ask.

## Phase 2 — Practise (personal and family web app)

- Web app: dashboard, lesson player, exercise library, workout planner and log, recovery check-in, manual meal log, body measurements.
- Used daily by Pankaj and family members, each with their own account.
- Design pass using references (for example Mobbin) once screens are being designed.

**Exit check:** the app is used for real training for at least a few weeks; the main pain points are fixed.

## Phase 3 — Share (free or beta users)

- Invite a small group of viewers to use the web app.
- Privacy policy, terms, a consent flow and data deletion in place (see the [business model](../business/business-model.md)).
- Decide the mobile technology and the AI assistant approach (see [DECISIONS.md](../DECISIONS.md)).

**Exit check:** beta users return week after week without prompting; it's clear what they would pay for.

## Phase 4 — Business (paid app)

- Mobile app for training and logging on the go.
- Built-in assistant, grounded in Fit360 content and passing the safety test set.
- Subscriptions and payments; support channel.
- Legal review before launch.

**Exit check:** first paying users; retention and support load that one founder can sustain.

## Ongoing

- New curriculum terms, each approved before its features are built.
- Evidence cards refreshed as research changes.
